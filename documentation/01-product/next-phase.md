# 下一阶段：内测上线底座

状态：第一批 P0 和 Gumroad 代码闭环已完成，等待受控真人内测与真实订单演练。

## 目标

把当前 Demo 改造成可供小范围真人用户持续使用的版本。系统必须能限制费用、保存记录、删除用户图片，并在失败后保持数据和额度一致；海外用户使用英文、邮箱账号和 Gumroad 美元订阅。

## P0 范围

### 1. 游客费用保护

- 游客首次请求即获得固定 HttpOnly 会话。
- 同时按会话和网络来源限制请求。
- 默认每 15 分钟最多 10 次、每天最多 30 次，可由环境变量收紧。
- 平台默认每天最多 100 个生成任务，达到上限后自动停止新任务。
- 登录用户继续受月度图片额度约束。
- 限流重启后仍然有效。

### 2. 任务与反馈持久化

- 方案、偏好、结果、用户选择和反馈写入数据库。
- 已登录用户可跨浏览器会话读取自己的历史记录。
- 游客只能读取当前会话记录。
- 服务重启后记录不丢失。

### 3. 真实删除和留存

- 删除任务时校验账号或游客会话所有权。
- 删除任务、反馈、生成资产数据库记录和实际图片文件。
- 过期图片不能访问，并提供批量清理能力。
- 生成任务的成本元数据保留，用于对账，但不保留人像内容。

### 4. 测试隔离

- 自动化测试使用独立临时数据库和图片目录。
- 测试不得写入 `data/hairstyle.db` 或 `data/generated`。
- 本地生成目录加入 Git 忽略规则。

## 本阶段不做

- 短信验证码和自建信用卡表单；支付信息由 Gumroad 托管。
- 完整门店 CRM。
- PostgreSQL 和云对象存储迁移。
- 正式的异步 Worker；该项放在下一阶段，但本阶段先保证失败后的额度和数据一致。

## 验收

- `npm run check` 全部通过。
- 连续重启服务后，历史任务和反馈仍可读取。
- 跨账号、跨游客会话读取或删除返回 `404`。
- 删除成功后，数据库与磁盘均不存在对应图片。
- 自动化测试前后，正式数据库和正式生成目录文件数不变。
- 限流超过阈值返回 `429`，重启服务后仍保持限制。

## 已完成验证

- SQLite 任务和反馈在服务重启后仍可读取。
- 跨游客会话删除返回 `404`，所有者删除返回 `200`。
- 删除任务后，任务和反馈记录均被清除；图片文件删除由自动化测试覆盖。
- 测试使用临时数据库和图片目录，正式库与正式图片目录测试前后均为 33 条。
- 三方案部分失败时清理残留图片，并把已知供应商成本计入失败任务。
