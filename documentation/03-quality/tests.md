# 测试基线

## 自动化覆盖

| 范围       | 已验证内容                                                     |
| ---------- | -------------------------------------------------------------- |
| 推荐规则   | 男女、长短发和目标长度返回三个有效方案                         |
| 账号与权限 | 密码哈希、登录限流、三层角色和任务所有权                       |
| 任务数据   | 任务、方案、选择和反馈重启后可恢复，跨主体不可访问             |
| 隐私与删除 | 结果真实删除、30 天清理、目录越界保护                          |
| 身份与额度 | 匿名生成拒绝、登录账号免费一次、主体与网络限流及全局任务上限   |
| 费用控制   | 排队承诺费用计入全局熔断，失败费用仍纳入统计                   |
| 生成队列   | 幂等提交、单次完成、自动重试、排队取消、僵死任务恢复           |
| 供应商     | RunningHub 提交、轮询、结果转存和成本聚合；测试不调用真实接口  |
| 密钥       | AES-256-GCM 加解密和篡改拒绝                                   |
| 监控告警   | 僵死任务、积压、失败率和费用规则开合                           |
| 备份       | SQLite 完整性检查、资产快照和备份记录                          |
| 测试隔离   | 每项持久化测试使用临时数据库、临时原图和结果目录               |
| Gumroad    | 一次性次数包幂等发放、退款拒绝、订阅激活、加密、重复绑定、取消、失效、故障宽限和门店共享额度；不调用真实接口 |
| Stripe备用 | 订阅权益发放与撤销、签名验证、重复事件去重；不调用真实支付接口 |

当前基线：18 个测试文件，47 项测试。执行：

```bash
npm run check
```

该命令依次执行 ESLint、TypeScript、全部测试和生产构建。

## 上线前人工演练

1. 使用独立测试目录启动应用和 Worker，完成提交、查询、选择、反馈、删除和重启恢复。
2. 重复提交同一幂等键，确认仅产生一个任务和一份费用承诺。
3. 模拟供应商 500、超时和 Worker 中断，确认重试、僵死恢复、额度释放和错误码正确。
4. 将费用上限降至最小值，确认新任务在写入前被拒绝。
5. 触发积压和失败率告警，确认运营台与 Webhook 均收到记录。
6. 创建备份，写入新数据，再恢复备份并核对数据库、图片和清单校验值。
7. 使用发布标签执行代码回滚演练。
8. 使用 Gumroad 真实测试订单完成购买、激活、取消、续费失败、退款和争议演练。
